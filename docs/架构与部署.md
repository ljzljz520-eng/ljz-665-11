# 架构与部署

## 总览

本项目采用前后端分离架构，并通过 Docker Compose 以“数据库初始化 → 后端 → 前端”的顺序启动：

- **db（SQL Server 2022）**：提供业务数据库服务。
- **db-init（初始化容器）**：将 MySQL 脚本转换为 SQL Server 脚本并初始化目标库。
- **redis**：后端缓存与会话相关能力依赖。
- **backend**：JeecgBoot 后端（Spring Boot）。
- **frontend**：JeecgBoot 前端静态站点（容器内 Nginx 提供访问）。

对应编排定义见 [docker-compose.yml](file:///Users/jack.yan/Downloads/labeleases/stage03/665/jeecg-boot/docker-compose.yml)。

## 容器与端口

- 前端：`http://localhost:3665`（容器 `jeecg-frontend`，端口映射 `3665:80`）
- 后端：`http://localhost:8665`（容器 `jeecg-backend`，端口映射 `8665:8080`）
- SQL Server：`localhost:1433`（容器 `jeecg-sqlserver`，端口映射 `1433:1433`）

## 启动流程

1. `db` 启动并暴露 SQL Server 端口。
2. `db-init` 等待 SQL Server 就绪后：
   - 确保数据库 `temp1218` 存在；
   - 将 `backend/db/jeecgboot-mysql-5.7.sql` 转换为 SQL Server 可执行脚本；
   - 执行 DDL + 种子数据初始化。
3. `backend` 使用 `sqlserver` profile 启动并连接到 `db`。
4. `frontend` 在 `backend` 可用后启动。

## 数据流

- 浏览器 → `frontend`（静态资源）
- 浏览器 → `backend`（API）
- `backend` → `db`（SQL Server）
- `backend` → `redis`

## 数据库初始化与转换器

初始化容器使用脚本 [convert_mysql_to_sqlserver.py](file:///Users/jack.yan/Downloads/labeleases/stage03/665/jeecg-boot/db/sqlserver/convert_mysql_to_sqlserver.py) 完成“DDL/数据插入语句”从 MySQL 方言到 T-SQL 的转换，重点能力包括：

- **类型映射**：常见整数、时间、文本、二进制、JSON 等转换为 SQL Server 对应类型。
- **MySQL 语法清理**：移除 `CHARACTER SET`/`COLLATE`/`COMMENT`/`UNSIGNED`/`ON UPDATE` 等 SQL Server 不支持的列后缀。
- **长 SQL 分割**：对超长 `INSERT` 语句进行切分，避免单条语句长度限制。
- **索引处理**：将 MySQL 的索引声明抽取为 `CREATE INDEX` 语句并在建表后执行。

为保证初始化脚本可在“全量建表 + 全量插入”场景稳定执行，转换器对部分约束做了兼容性取舍：

- **外键约束**：初始化脚本会跳过外键相关语句（避免跨表依赖导致初始化失败）。
- **唯一约束**：为降低“历史数据与索引唯一性不一致”引发的失败概率，转换器将唯一索引降级为普通索引（依赖应用层约束与业务校验）。

## 配置入口

### Docker 环境变量

- `MSSQL_SA_PASSWORD`：SQL Server `sa` 密码（默认 `Supcon1304`）。

### 后端关键配置（容器环境变量）

- `SPRING_PROFILES_ACTIVE=sqlserver`
- `SPRING_DATASOURCE_DYNAMIC_DATASOURCE_MASTER_URL=jdbc:sqlserver://db:1433;...;DatabaseName=temp1218;...`
- `SPRING_DATA_REDIS_HOST=redis`
