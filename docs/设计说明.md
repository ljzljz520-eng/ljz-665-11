# 设计说明

## 设计目标

- **一键可用**：无需手工导入 SQL，`docker compose up -d` 后即可访问前后端。
- **方言适配**：将官方 MySQL 初始化脚本在启动时转换为 SQL Server 可执行脚本。
- **可回放**：初始化过程可重复执行（可通过重建数据库 + 重新运行 `db-init` 回放）。

## 关键设计

### 1) 以初始化容器承载“脚本转换 + 建库 + 导入”

原因：

- 避免在开发者本机安装额外工具链（Python/SQL Server 工具/手工执行 SQL）。
- 将初始化过程固化为可重复的镜像构建与容器启动行为。

实现：

- `db-init` 使用 [db/sqlserver/Dockerfile](file:///Users/jack.yan/Downloads/labeleases/stage03/665/jeecg-boot/db/sqlserver/Dockerfile) 构建。
- 入口脚本 [entrypoint.sh](file:///Users/jack.yan/Downloads/labeleases/stage03/665/jeecg-boot/db/sqlserver/entrypoint.sh) 负责等待 SQL Server 就绪、创建库、执行转换与导入。

### 2) 数据库方言兼容策略

MySQL 脚本包含大量 SQL Server 不支持的语法与类型（如 `json`、`varchar(5000)`、`USING BTREE`、列注释、字符集、`ON UPDATE CURRENT_TIMESTAMP` 等）。为保证全量导入可成功执行，转换器采用“能执行优先”的策略：

- **类型映射**：
  - `json` → `nvarchar(max)`
  - `varchar(n)`：当 `n > 4000` 时 → `nvarchar(max)`
  - `float(m,n)` / `double(m,n)` → `decimal(m,n)`（保留精度语义）
  - `datetime` / `timestamp` → `datetime2`
- **列修饰清理**：移除 `CHARACTER SET` / `COLLATE` / `COMMENT` / `UNSIGNED` / `ZEROFILL` 等。

### 3) 约束与索引处理

为了提升“全量初始化一次成功”的概率，特别是在存在历史数据不满足唯一性或跨表依赖时：

- **外键**：跳过外键声明，避免按建表顺序导致的 `REFERENCES` 失败。
- **唯一索引**：统一降级为普通索引，避免因数据重复导致初始化失败。

该取舍适用于演示/开发环境一键启动；如在生产环境需要强约束，应在数据清洗后补充唯一约束与外键。

### 4) 种子数据导入稳定性

MySQL 脚本中部分 `INSERT` 行非常长，且 SQL Server 对单条语句长度/执行参数有更严格限制。转换器支持对长 `INSERT` 语句按逗号边界切分，以降低导入失败概率。

## 目录与模块边界

- `backend/`：后端 Java（Maven 多模块）。
- `frontend/`：前端 Vue3（Vite 构建，容器中由 Nginx 提供静态资源）。
- `db/sqlserver/`：SQL Server 适配与初始化组件（转换器与入口脚本）。
- `backend/db/`：官方初始化 SQL（来源为 MySQL 版本脚本）。
